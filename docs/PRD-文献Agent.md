## 1. 背景与问题

写开题/综述时，找文献 + 粗读 + 整理引用要 2-3 天。现有工具断成两截：网页搜索工具（如原版 local-deep-researcher）**根本不检索学术库**——搜"国际金融"返回词典页和新闻站，且没有相关性筛选，噪声直接进总结；人工检索则慢在机械环节（翻译检索式、筛相关、读摘要、对格式）。

**判断**：这不是"搜得不够多"，是**流水线缺环节**。产品要做的是补齐"检索 → 筛选 → 精读 → 成文 → 核验"的整条链，而不是再做一个聊天框。

## 2. 目标与指标

**目标**：输入一个中文研究主题，6-8 分钟内产出**结构完整、引用可追溯**的中文综述初稿（默认 2 轮 × 5 篇）。

| 指标 | v1.0 验收线 |
|---|---|
| 检索源 | 100% 学术库（Crossref + DOAJ + arXiv），0 个网页搜索结果混入 |
| 引用核验 | 正文引用编号 100% 有效；输出「数字可追溯率」与需人工核对清单（核验为秒级确定性检查，不由模型自评） |
| 产出结构 | 综述正文 + 对比表 + 参考文献带 DOI，三件齐全 |
| 可复现 | 同一主题两次运行的引用列表均来自真实可访问的 DOI |
| 上手成本 | 新电脑双击 `一键安装.bat` 到跑通自检 ≤15 分钟 |

## 3. 用户与场景

| 用户 | 场景 | 用户故事 |
|---|---|---|
| 学生/研究者（核心） | 开题找文献 | 作为学生，我给一个中文主题就拿到筛好的文献清单和综述初稿，这样把 2-3 天压到 1 小时内（AI 初稿 + 人工精修） |
| 学生 | 读单篇论文 | 作为学生，我想把一篇 PDF 压成"问题/方法/数据/发现/局限"卡片 |
| 学生 | 精读中提问 | 作为学生，我想针对论文内容追问，且回答必须引用原文位置 |
| 有文献库的用户 | 边写边查 | 作为作者，我想对自己的文献库提问 |

## 4. 本期范围（v1.0 做了什么 / 不做什么）

**做**：五个入口（综述 Agent / 精读 / 论文对话 / 文献库对话 / Streamlit 网页界面）、学术库检索与三因子打分、模型复筛、精读卡片、缺口驱动的补充检索、引用核验、本地模型（Ollama）、一键安装 + 11 项自检。

**不做（及理由）**：
- ❌ 全文下载与盗版源——只用开放元数据与开放获取库，合规红线；
- ❌ 云端模型依赖——本地优先（隐私 + 0 成本），云端接口保留为可选项；
- ❌ 自动写"能直接交"的综述——定位是**初稿引擎**，产出必须经人工核对（核验清单就是为此设计）；
- ❌ 引文格式全家族支持——v1 只保证 DOI 可追溯，APA/GB7714 导出列 M2。

## 5. 功能需求与验收标准

### F1 文献综述 Agent（P0，已上线）

- F1.1 检索式生成：把中文主题翻译为学术英文检索式。
  **验收**：主题「大语言模型在金融风控中的应用」产出形如 `large language model credit risk` 的英文检索式（不逐词直译）。
- F1.2 多库检索：Crossref（期刊）+ DOAJ（开放获取）+ arXiv（预印本），合并去重。
- F1.3 双层筛选：代码按相关性/引用数/新近度打分排序 → 模型复筛一遍"是否真的相关"。
  **验收**：网页词典/新闻类结果出现率为 0（与原版工具的本质差异）。
- F1.4 逐篇精读：每篇压成「问题/方法/数据/发现/局限」五元卡片。
- F1.5 缺口驱动补检：从已读卡片识别知识缺口，再跑一轮检索（默认 2 轮，`--rounds` 可调 1-3）。
  **验收**：`--rounds 1 --papers 3` 快速模式约 3 分钟完成。
- F1.6 成文：中文综述 + 文献对比表 + 参考文献列表（含 DOI）。

### F2 引用核验（P0，已上线，本产品的信任底座）

- F2.1 编号核验：正文 `[n]` 与参考文献表一一对应，无效编号报出。
- F2.2 数字核验：正文中的关键数字回所引论文的可验证字段追溯，输出**数字可追溯率** + 需人工核对清单。
  **验收**：核验为确定性代码检查（秒级），不依赖模型自评；报告随综述一并输出。
- **设计立场**：模型负责写，代码负责"证"。核验不过的内容必须可见，不允许静默通过。

### F3 精读与对话入口（P1，已上线）

- F3.1 `run_paper_read.py`：单篇 PDF → 五元精读卡。
- F3.2 `run_paper_chat.py`：针对单篇论文问答，回答须引用原文依据。
- F3.3 `run_library_chat.py`：对本地文献库提问。
  **验收**：三个入口可独立运行，均不依赖综述 Agent 的中间产物。

### F4 交付与上手（P0，已上线）

- F4.1 一键安装（Windows `一键安装.bat` / macOS `一键安装.command`）：建环境、装依赖、生成配置、跑自检。
- F4.2 自检 11 项（`环境自检.bat` / selftest），覆盖网络、依赖、模型可用性、检索连通。
  **验收**：新机器安装后自检全绿才进入使用；任一项失败给出排错指引。
- F4.3 网页界面（`启动界面.bat` → Streamlit :8501）：给不用命令行的用户。
- F4.4 全流程本地：默认 Ollama（qwen2.5:3b/7b），论文数据不出本机（检索元数据除外）。

## 6. 关键流程（综述入口）

中文主题 → 英文检索式 → 三库检索去重 → 打分排序 → 模型复筛 → 逐篇精读（五元卡）→ 缺口识别 → 补充检索（第 2 轮）→ 中文综述 + 对比表 + 参考文献 → 引用核验（编号 + 数字可追溯率 + 人工核对清单）→ 交付。

## 7. 非功能需求

- **隐私**：正文处理全本地；仅检索元数据出网（公共学术 API）；
- **成本**：本地模型 0 元；无云端依赖项；
- **性能**：标准模式（2 轮 × 5 篇）6-8 分钟（笔记本 CPU 可跑）；快速模式 3 分钟；
- **健壮性**：单库超时/失败降级为其余库继续，结果页注明缺库；
- **诚实性**：所有"AI 说了"与"代码验了"分开呈现，可追溯率是硬数字。

## 8. 风险与开放问题

| 风险 | 应对 |
|---|---|
| 本地小模型精读深度有限 | 卡片结构化约束输出 + 核验兜底；提示换更大模型/云端 |
| 学术 API 限流或变更 | 多库冗余 + 失败降级 + 自检项覆盖连通性 |
| 综述被直接交差（误用） | 产品文档明示"初稿 + 必须人工核对"；核验清单强化这一点 |

**开放问题**：Zotero/BibTeX 导出的格式优先级；中文社科库（如知网）无开放 API，如何合规扩展。

## 9. 发布计划

- **M1（已发布）**：F1-F4 全部五个入口 + 引用核验 + 一键安装；
- **M2**：BibTeX/Zotero 导出、综述分段人工确认后再续写、跨库去重的引用合并视图。
