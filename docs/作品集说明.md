# 作品集说明：本地文献综述 Agent

> 这是一个可以放进简历 / 面试讲的完整产品案例。下面按"产品经理讲作品"的结构写：
> 问题 → 方案 → 架构 → 关键取舍 → 竞品对比 → 指标 → 复盘与下一步。

---

## 一、一句话介绍

**一个跑在本地笔记本上的文献综述 Agent：输入中文研究主题，自动检索期刊与预印本、
逐篇结构化精读、生成带 DOI 的中文综述初稿，全程不需要付费 API。**

技术栈：`LangGraph` + 本地 `Ollama (qwen2.5)` + `Crossref / DOAJ / arXiv` 开放学术接口。

---

## 二、问题是什么

做研究、写行业报告、准备面试时，真实痛点是：

1. **搜不准**：用通用搜索引擎搜学术问题，返回的是新闻、百科、词典和 SEO 垃圾；
2. **读不完**：一个方向动辄几百篇论文，粗读一遍要几天；
3. **留不住**：读完记不住"谁用了什么方法、在哪份数据上得出什么结论"；
4. **引不对**：模型总结时容易编造引用和数字，没法直接用于正式材料。

现有 AI 产品大多解决"读一篇"（ChatPDF 类），很少解决"**一个领域的文献综述**"。

## 三、方案与架构

```mermaid
flowchart TD
    A[用户输入中文主题] --> B[plan_queries<br/>生成 3 条英文学术检索式<br/>+ 核心概念 + 中文检索式]
    B --> C[search<br/>Crossref 期刊 + DOAJ 开放期刊 + arXiv 预印本]
    C --> D[去重 + 相关性打分<br/>关键词 / 核心概念 / 引用数 / 年份]
    D --> E[screen<br/>模型二次筛选 top-N]
    E --> F[read<br/>逐篇结构化精读<br/>问题/方法/数据/发现/局限]
    F --> G{达到轮数?}
    G -- 否 --> H[reflect<br/>找知识缺口 → 新检索式]
    H --> C
    G -- 是 --> I[synthesize<br/>主题化中文综述 + [n] 引用]
    I --> V[verify<br/>引用核验：编号有效性<br/>+ 数字回查]
    V --> J[finalize<br/>Markdown 报告<br/>对比表 + 参考文献 + 核验指标]
```

入口：

| 入口 | 场景 | 输出 |
|---|---|---|
| `app.py`（Streamlit） | 网页界面，演示 & 日常使用 | 5 个标签页：综述 / 精读 / 论文对话 / 文献库 / 说明 |
| `run_lit_review.py` | 命令行跑综述 | 中文综述 + 对比表 + 参考文献 |
| `run_paper_read.py` | 精读单篇 / 知网 PDF 批量对比 | 结构化精读笔记 / 横向对比综述 |
| `run_paper_chat.py` | 和一篇论文连续对话 | 问答 / 可写观点卡 / 原文引文 |
| `run_library_chat.py` | 多篇论文组成的文献库 | 跨文献问答 / 对比表 / 共同研究空白 |

## 四、五个关键设计决策（面试重点）

### 决策 1：把"网页搜索"换成"学术检索"

原版工具（`local-deep-researcher`）用的是 DuckDuckGo 网页搜索。同样是"国际金融"，
返回的是词典页和新闻站——**不是模型不行，是数据源根本不对**。

换源之后：Crossref 覆盖正式期刊论文（含 DOI、期刊、引用数），DOAJ 补充开放获取期刊，
arXiv 覆盖最新预印本。全部免费、无需 key、可商用（OpenAlex 填 key 后更全）。

> 这条经验可以迁移到任何 RAG / Agent 产品：**检索层的质量决定了生成质量的上限**，
> 提示词优化救不了错的数据源。

### 决策 2：加一个显式的"相关性硬约束"

模型生成检索式时很容易把主题词丢掉（"大语言模型在金融风控中" → 只搜 `financial risk`），
结果搜回来一堆只沾领域边的论文。三个处理：

1. 提示词要求每条检索式必须包含核心概念；
2. 代码兜底：检索式里没有核心概念就自动补上；
3. 打分时对"完全不提核心概念"的论文扣分（`-8`），让它进不了精读环节。

第一次实测时正是因为缺这一步，综述里写满了"金融欺诈检测"，却一个字没提大语言模型。

### 决策 3：不让模型直接读全文，而是先压成结构化卡片

- 每篇论文先抽成 7 个字段（问题 / 方法 / 数据 / 发现 / 局限 / 相关性 / 一句话），
  再把这些卡片交给合成环节；
- 好处：① 3B 小模型的上下文扛得住；② 综述有稳定的结构；③ 卡片是**结构化数据**，
  可以导出 JSON 复用到别处；
- 参考文献由**程序从检索元数据生成**，不让模型自己"回忆"作者和 DOI，从源头减少编造。

### 决策 4：把"引用核验"做成确定性指标，而不是让模型自评

最开始我想做的引用核验是"让模型逐句判断观点能否被摘要支持"。实测发现：

* 同一份稿子跑两次，**语义支持率从 33.3% 变成 27.3%**——3B 模型给自己打分不稳定，
  这种指标没法写进作品集，也没法用来判断质量；
* 真正高价值、可复现的是**确定性检查**：
  1. 正文 `[n]` 是否都对应真实参考文献（编号有效性）；
  2. 正文里的百分比/小数/样本量，能否在所引论文的摘要或精读卡片里找到（**数字回查**）；
  3. 哪些参考文献"挂着但没被引用"。

所以最终方案是：**主指标用确定性检查，语义抽检降级为可选参考**（默认关闭）。
这一步的经验是：**能用规则算出来的指标，就不要交给模型判断**——
这也是我在产品设计里最想强调的一条。

### 决策 5：论文对话不用向量库，用"可复现的词法检索 + 程序回填原文"

做"和一篇论文对话"时，第一个直觉是上 embedding + 向量库。实际做了三个判断：

1. **一篇论文只有几十个片段**，BM25 词法检索足够，而且**同样的提问永远命中同样的原文**——
   可复现、可核对页码，调试成本远低于向量检索；
2. 中英混排用「英文词 + 中文字符二元组」分词；**中文提问自动用模型压成英文关键词再检索**，
   否则英文论文召回为 0（这是实测踩到的第一个坑）；
3. 最关键的一条：**"提炼可写进论文的观点"时，原文依据不让模型复述**。
   做法是把检索到的片段拆成句子并编号（`[p3-s2]`），模型只输出句子编号，
   由程序把真实原句回填进卡片——小模型"假装引用"的问题被从结构上消灭了。

> 这条和决策 4 是同一个思路：**能把可靠性交给代码的，就不要交给模型**。

## 五、和现成开源项目比，为什么不直接用

调研时间 2026-10，star 数为当时实测：

| 项目 | 定位 | 为什么没直接用 |
|---|---|---|
| [paper-qa (PaperQA2)](https://github.com/Future-House/paper-qa) | 论文库 RAG 问答，9.5k★ | 强在"读已有 PDF 并回答"，但**自己不负责找文献**；需要 embedding + 索引，本地跑更重。适合做"读"，不适合做"综述" |
| [STORM](https://github.com/stanford-oval/storm) | 维基式长文生成，31.7k★ | 大纲驱动写作很棒，但检索基于通用搜索/维基，学术性弱，本地小模型支持一般 |
| [gpt-researcher](https://github.com/assafelovic/gpt-researcher) | 通用 deep research，30.3k★ | 能力强但偏通用网页研究，且是完整大项目，**改造成本 > 自己写核心链路** |
| [paper-search-mcp](https://github.com/openags/paper-search-mcp) | 多源论文检索 MCP，2.9k★ | 只做检索，不做综述；可以作为工具层参考 |
| [arxiv-mcp-server](https://github.com/blazickjp/arxiv-mcp-server) | arXiv 全文读取，3.2k★ | 只覆盖 arXiv，没有期刊 |

**结论**：现有项目要么只做"读"、要么只做"搜"、要么是重型通用 Agent。
"中文主题 → 学术检索 → 结构化精读 → 中文综述"这条链路是空档，而且用现有
`local-deep-researcher` 的 LangGraph 骨架改造，成本最低。

## 六、可以量化的指标（作品集里最好写数字）

跑一次综述会自动产出这些可度量项（`output/*.json` 里有结构化数据）：

| 指标 | 怎么算 | 当前实测（qwen2.5:3b） |
|---|---|---|
| 一次综述耗时 | 端到端墙钟时间 | **约 6 分钟**（8 篇精读 + 引用核验，CPU 推理） |
| 检索召回 | 去重后候选论文数 | **181 篇**（第 1 轮，4 条检索式 × 3 个源） |
| **检索层 A/B（10 主题）** | B0 直接检索 / B1 检索式 / B2 硬淘汰 / B3 软惩罚 | v1：6.0%→60.0%→66.0%；v2（repeat 2）：6.0%→57.5%→64.5%→62.0%。**只有 B0→B1 稳健**；B2/B3 差异在 ±11~14pp 噪声内 |
| **v2 的结论** | 同义词扩展 + 软惩罚 | **未提升 Precision@10**，原因是评测构念效度：判定与硬约束同源，看不见"同义词误杀"；需人工标注 100 篇验证 |
| 引用编号有效性 | 正文 `[n]` 能对应到参考文献的比例 | 23/23 = 100%，但这是**结构下限**（参考文献由程序生成），不是质量 |
| 参考文献使用率 | 被正文引用过的参考文献占比 | 7/8 |
| 数字可追溯率 | 正文数字能在所引论文里找到的比例 | 100%，但样本只有 2 个数字，不宣称准确率 |
| 引用语义支撑率 | 模型判断观点是否有依据 | 33.3% / 27.3%（同稿两次），**不可复现，已降级为参考** |
| 数字幻觉 badcase | 人工抽查"数字能否在原文找到" | 3B 实测：单篇精读把 ToT 的 74% 写成 87.8%（**已知 badcase**） |

> **诚实说明**：87.8% 那个例子是我自己实测抓到的问题，已写进提示词的"反幻觉规则"，
> 但 3B 模型仍不能保证准确。**所有数字必须回原文核对**——这也是产品边界的一部分。

## 七、下一步可以做什么（v2 roadmap）

按投入产出排序：

1. ✅ **引用核验节点**（已做）：编号有效性 + 数字回查（确定性），语义抽检作为可选参考。
2. ✅ **Web UI**（已做）：Streamlit 5 个标签页，主题输入 / 实时进度 / 指标卡 / 报告下载 / 单篇精读 / 论文对话 / 文献库。
3. ✅ **云端模型切换**（已做）：界面里可切 DeepSeek / OpenAI / 通义，无需改配置文件。
4. ✅ **论文对话 Agent**（已做）：BM25 检索 + 多轮问答 + 可写观点卡（原文由程序回填）+ 引文摘录。
5. ✅ **文献库对话**（已做）：多篇论文跨文献问答、对比表（逐篇抽取 + 程序拼表）、共同研究空白。
6. ✅ **10 主题检索层 A/B 评测**（已做）：v1 B0 6%→B1 60%→B2 66%；v2（repeat 2）B0 6%→B1 57.5%→B2 hard 64.5%→B3 soft 62.0%。
7. ✅ **用户测试套件**（已做）：主试话术 / 任务卡 / 计时器 / SUS / 自动分析，待采集 5 人数据。
8. ✅ **模型对比**（已做）：3B vs 7B，抽取有效字段率 80% → 100%，耗时 2.8×。
9. ✅ **v2 同义词扩展 + 软惩罚**（已做，默认 `soft`）：消除硬约束误杀风险；**但实测未提升 Precision@10**——发现评测存在构念效度问题（指标与硬约束同源）。
10. **人工标注 100 篇**（2 人交叉）：验证 v2 的召回收益，这是"v2 是否真的更好"的唯一可信方式。
11. **5 人可用性测试**：跑完把数据放进 `user_test/results/`，`analysis.py` 自动出报告。
12. **引文滚雪球**：对已入选论文用 OpenAlex 的 `referenced_works` / `cited_by` 追引文。

> 📦 **发布用成品在 `portfolio/` 目录**：架构图、产品案例、样例产出、界面截图；仓库根目录的 `README.md` 与 `index.html` 分别是 GitHub 首页与个人网页。

## 八、面试怎么讲（3 分钟版本）

> "我做过一个本地文献综述 Agent。起因是我自己要看论文，发现通用 AI 搜索给的参考文献
> 经常是网页甚至假引用。我把它拆成四步：检索、筛选、精读、核验。
> 检索层我换掉了网页搜索，改用 Crossref、DOAJ、arXiv 这些开放学术接口，免费而且有 DOI；
> 筛选层我发现模型会丢掉核心概念，所以加了'检索式必须含核心概念'的硬约束和打分惩罚；
> 精读层不让模型直接读全文，而是先抽成结构化卡片，参考文献由程序从元数据生成。
> 最后我加了一个引用核验环节：检查编号是否有效、数字能不能在原文找到。
> 这里有个踩坑：我本来想让模型自己判断'观点有没有依据'，但同一份稿子跑两次，
> 判定结果能差 6 个百分点，所以我把它降级成参考，主指标改成确定性的数字回查。
> 后来需求变成'能围绕一篇论文提问'，我做了论文对话：中文问题自动转英文检索，
> 提炼观点时让模型只给句子编号、程序回填原文，避免它假装引用。
> 整个东西跑在本地 Ollama 上，不花钱、不上传数据，也有 Streamlit 界面可以演示。"
> 目前一次综述约 6 分钟、覆盖 8 篇文献，输出带 DOI 和核验指标的中文初稿。

**大概率被追问的问题：**

| 问题 | 怎么答 |
|---|---|
| 为什么不用现成的 paper-qa / gpt-researcher？ | 它们分别只解决"读"或"通用网页研究"，而且改造成本高于自己写核心链路。我在作品集里做了竞品对比表 |
| 3B 模型幻觉怎么办？ | 三层：结构化卡片约束输出格式、参考文献由程序生成、数字回查把可疑数字列出来让用户核对；badcase 已写进提示词 |
| 怎么评估效果？ | 确定性指标：引用编号有效率、数字可追溯率、参考文献使用率；语义抽检因小模型判定不稳定已降级为参考。v2 会做 10 主题评测集 |
| 为什么把语义核验降级？ | 同一稿两次语义支持率 33.3% → 27.3%，说明指标不可复现。产品里**不可复现的指标比没有指标更危险**，会误导用户和迭代方向 |
| 论文对话为什么不用向量库？ | 一篇论文几十个片段，BM25 就够，而且检索结果可复现、能核对页码；向量检索调参成本高、小模型 embedding 还会引入额外依赖。真要做跨文献库问答再上 RAG |
| 怎么保证对话不瞎编？ | 回答必须标页码、片段里没有就明说"未提到"；观点卡的原文依据由程序从句子编号回填，不是模型复述 |
| 这个产品的边界在哪？ | 它是"综述初稿 + 线索发现"，不是终稿；中文库（知网）走本地 PDF 而非爬虫，合规 |
