# 用户测试方案（5 人可用性测试）

> 目的：回答一个作品集里最容易被追问、也最不能用代码解决的问题——
> **"这个东西真的比手工快吗？别人能用起来吗？"**

---

## 一、测试要回答的三个问题

| 编号 | 问题 | 指标 |
|---|---|---|
| RQ1 | 找文献是否更快？ | 任务 1 耗时（手工 vs 工具），成功率 |
| RQ2 | 能用它产出可用的综述素材吗？ | 任务 2 产出中"可写进论文的观点"数量与质量评分 |
| RQ3 | 主观可用性如何？ | SUS 量表得分（0-100） |

> 样本量 5 人是可用性测试的经典下限（Nielsen：5 人能发现约 85% 的可用性问题）。
> 结论只做定性 + 描述统计，**不做显著性检验**——5 个人做不了统计推断，别硬吹。

---

## 二、设计

- **被试**：5 人，最好是"写过文献综述 / 做过行业研究"的同学（本科高年级、研究生、实习过的都行）；
- **设计**：**被试内对照**——每人两个条件，顺序随机（A 先手工 / B 先工具），避免学习效应；
- **主题**：每人一个不同主题（从下面 5 个里随机分配，避免互相抄答案）：

| # | 主题 |
|---|---|
| T1 | 大语言模型在金融风控中的应用 |
| T2 | ESG 投资与企业绩效 |
| T3 | 供应链韧性 |
| T4 | 医学影像分割的深度学习方法 |
| T5 | 碳中和政策对企业的影响 |

- **时长**：每人 60 分钟（15 分钟说明 + 20 分钟手工 + 20 分钟工具 + 5 分钟问卷）；
- **环境**：被试自己的电脑；工具用网页界面（`启动界面.bat`）；
- **伦理**：匿名编号（P1-P5），不录屏，只记录时间与结果；测试前口头告知并征得同意。

---

## 三、测试流程（主试照做）

| 时间 | 环节 | 做什么 |
|---|---|---|
| 0-5 min | 说明 | 念 `facilitator_script.md` 开场；强调"测的是工具不是你"，随时可以放弃 |
| 5-10 min | 基线熟悉 | 给被试看任务说明，确认理解（不演示工具） |
| 10-30 min | 条件 A：**手工** | 用搜索引擎 / 学校数据库找 10 篇相关文献，记录耗时与找到的篇数 |
| 30-50 min | 条件 B：**工具** | 用本工具跑同一个主题，记录耗时；再挑 3 条"可写进论文的观点" |
| 50-55 min | SUS 问卷 | 10 道题（1-5 分） |
| 55-60 min | 访谈 | 3 个开放问题：最有用 / 最困惑 / 会不会继续用 |

**主试规则（很重要）**：
1. 只在被试卡住超过 2 分钟时给**中性提示**（"你可以试试左侧的设置"），不教操作；
2. 记录被试**第一次卡住的地方**（这是产品问题，不是被试问题）；
3. 不评判、不解释设计、不说"这个功能其实……"；
4. 全程用 `user_test/timer.py` 记录时间，别事后回忆。

## 四、文件说明

```
user_test/
├── README.md               ← 本文件（主试读）
├── facilitator_script.md   ← 开场白 + 中性提示话术 + 访谈问题（照着念）
├── task_sheet.md           ← 给被试看的任务卡（打印或发链接）
├── record_template.csv     ← 每个被试一行，主试填
├── sus_template.csv        ← SUS 10 题，每行一个被试
├── timer.py                ← 命令行计时器：自动写 CSV，避免手工记错
└── results/                ← 真实测试数据放这里（已在 .gitignore 里，不要提交）
```

**跑完 5 人后**：

```bash
.venv\Scripts\python.exe user_test/analysis.py user_test/results
```

会自动生成 `user_test/results/RESULTS.md`：任务耗时对比、成功率、SUS 得分、可用性问题清单。

## 五、指标定义（写进作品集时照这个口径）

| 指标 | 定义 |
|---|---|
| 任务 1 耗时 | 从"开始找"到"找到 10 篇并说明为什么相关"的墙钟时间 |
| 任务 1 成功率 | 10 篇里被主试判定"确实相关"的篇数 / 10 |
| 任务 2 观点可用率 | 3 条观点中，被试认为"可以直接写进论文"的条数 / 3 |
| SUS | 标准 10 题，按标准公式换算成 0-100 |
| 卡点 | 主试记录的"第一次卡住"位置，按界面/概念/等待分类 |

---

## 六、诚实的预期管理

- 5 人测试的结论是**方向性的**，不是统计显著的；
- 被试是同学，存在"给面子"偏差 → 访谈里明确说"说难用不会得罪我，反而帮到我"；
- 工具用本地 3B 模型，**等待时间偏长**是已知问题，测试时要如实记录等待时长，
  这正好可以作为"换 7B / 云端模型"的依据。
